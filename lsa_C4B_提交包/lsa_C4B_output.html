引言：一个正在被重新定义的岗位

过去，一个组织要发布内容，通常需要「编辑 + 排版 + 运维」三个人。今天，一个人 + 一个 AI + 一个发布技能，就是一个完整的内容工厂。

这不是口号，而是我在本次挑战里真实跑通的一件事：我拿一份开源 starter kit，改造成自己的公众号文章生成技能，然后用它把现在这篇文章排出来。

这篇文章想讲清楚的，不是「怎么用某个工具」，而是一个更根本的问题：在 AI 时代，个人能力如何被产品化、被复制、被放大。

痛点：公众号排版的五个「坑」

如果你在公众号后台贴过 Markdown 或 Word，一定踩过这些坑。公众号编辑器非常「挑剔」，规则冷冰冰地摆在那里：

坑 表现 后果
只认 inline CSS 不能用 <style>、不能用 class 排版全靠手点
禁止 h1 / div 一级标题被降级、div 不渲染 层级错乱
图片走 CDN 外链图片丢失、SVG 消失 配图蒸发
交互全失效 script / iframe 被剥掉 动效归零
移动端窄屏 表格过宽、字号过小 阅读体验差

⚠️ 注意 其中最隐蔽的是「SVG 保存即消失」——你精心画的矢量图，保存草稿再打开就没了。图片务必用 PNG。

这些坑叠加在一起，结果是：「内容很好」和「发布出来很好」之间，隔着一道巨大的排版鸿沟。

解法：把「格式转换」产品化成一个技能

我的解法不是「一篇一篇手动排」，而是把这套转换逻辑固化成一个技能。

核心就一条流水线：

Markdown / Word 文档 ↓ 读取源文件 ↓ 转 HTML ↓ 清洗违规标签 + 应用公众号排版规则 ↓ 输出 copy-paste ready 的 HTML ↓ 粘贴发布

技能做的是「确定性」的部分——清洗、过滤、加样式；我做的是「判断」的部分——写什么、什么观点、什么风格。

📘 知识点 微信只允许 p, h2, h3, ul, ol, li, span, img, a, table, tr, th, td, br 这十几个标签。凡是不在这个白名单里的，技能都会自动降级或删除。

拿来主义：理解 → 改造 → 超越

我没有从零写代码，而是「拿来」。但拿来主义不是复制粘贴，它有三个层次：

  1. 理解——先跑通原版，读每一段代码，搞清楚每个函数在做什么。
  2. 改造——找到它「缺什么」，再决定「加什么」。
  3. 超越——让新能力真正解决我自己的真实需求。

我在原版基础上新增了 6 项能力，每一项都对应一个真实痛点：

  • 多主题：同一篇文章，一键换风格，不用重排。
  • callout 框：知识点、提示、注意、实践，四种框是公众号的核心排版元素。
  • 自动目录：长文从标题自动生成目录。
  • 文章元数据：标题、作者、日期、摘要一次到位。
  • 页脚版权：发布必带的版权声明自动追加。
  • 中文排版：中英文之间自动加空格，专业感立现。

💡 提示 判断一个技能该加什么能力，标准只有一个：它能不能让你的「输入 → 输出」更顺滑。凡是能，就值得加；不能，就是炫技。

元技能：用「做技能的技能」做技能

这个过程中，最反直觉的一点是：我是用另一个技能（skill-creator）来做这个技能的。

这就是 Agent 系统里最迷人的「递归」——技能本身也是一种产物，可以用工具生产工具。skill-creator 引导我走完「定义目标 → 讨论边界 → 写指令 → 建测试用例 → 跑 eval → 迭代」的正规流程，而不是拍脑袋瞎写。

🔧 实践 你也试试：找一件你一周内重复做过 3 次以上的事，问自己「能不能打包成 输入 X → 输出 Y」，然后用 skill-creator 把它做出来。

一个技能背后的一整套系统

技能只是引擎，真正让内容持续产出的是一套 SOP。我把它沉淀成四步：

  1. 选题——想清楚「给谁看、解决什么问题」。
  2. 写稿——AI 辅助写初稿，我负责观点和取舍。
  3. 转换——一条命令生成公众号 HTML，浏览器预览、微调。
  4. 发布 + 复盘——粘贴发布，记下阅读数据，反哺下一篇。

这一步让我真正理解了挑战文档里那句话：C4 是把能力变成产品，C4B 是把「内容生产过程」变成产品。

写在最后：先交比不交强

回看整个过程，我最大的感受是：「完美」是「交付」的敌人。

第一版技能其实很粗糙，callout 解析还有 bug，中英文空格也是后来才补的。但如果我一开始就追求完美，可能现在还停在「要不要做」的阶段。

正确的顺序是：先跑通 → 先发布 → 再迭代。

内容工厂的雏形，是从第一篇真正发出去的文章开始的。而这篇，就是我的第一篇。
